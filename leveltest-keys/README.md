# 레벨테스트지 분석 키

학년별 레벨테스트지를 만드는 Claude 프로젝트(**레벨테스트지 제작**)가 테스트지와 함께 내는 JSON. academy-os가 가져와서 틀린 문항의 **근본 원인 분석**에 쓴다(`app/js/analysis.js`).

- 문항 본문은 담지 않는다(ENG-DIAG-08). 번호·정답·역량 태그·오답 보기 해석, 서술형·영작의 **모범 답안**(`model`, 리포트에 표시)만 담는다. 문항 그림은 원장이 리포트 칸에 캡처로 붙인다.
- 키를 고치면 `form.version`을 올린다. 앱 내장본은 버전이 더 높을 때만 저장된 키를 바꾼다.
- **부분 점수 없음**(2026-10-24): `err` 설명에 점수를 쓰지 않는다. 오류 유형은 "왜 틀렸는지"만 기록한다.
- **(보류) 문항 위치 지도**: 시험지 사진 자동 분할용. 아래 '시험지 사진 자동 분할' 참고.
- 파일명: `{학년}-{연-월}.json` (예: `ms1-2026-10.json`). `form.id`가 같으면 앱이 덮어쓰지 않으므로, 시험지를 고치면 `form.id`/버전을 바꿔 새로 가져온다.
- 앱 사용: 상담·등록 › 레벨테스트 › **테스트지 키 가져오기**. 내장본은 `app/data/leveltest-forms.js`(이 폴더 JSON에서 생성).

## 시험지 사진 자동 분할 (보류, 2026-10-25)
**시작 조건: 레벨테스트지 확정.** 문항이나 배치가 바뀌면 마크와 위치 지도를 다시 만들어야 해서, 최종본이 나온 뒤에 시작한다. 판정(틀린 번호 탭)은 지금처럼 사람이 하고, 자동으로 하는 건 **자르기만**이다(2026-10-24 결정).

| 단계 | 할 일 | 결과물 |
|---|---|---|
| ① 정렬 마크 | 시험지 docx 머리글에 네 모서리 검은 사각형(약 8mm, 종이 끝에서 약 8mm 안쪽, 주변은 흰 여백)을 넣어 모든 쪽 같은 위치에 찍히게 한다. 원본은 두고 마크 넣은 사본을 만든다. 인쇄·사진 미리보기를 보여 드리고 승인받는다 | 마크 넣은 시험지 docx |
| ② 문항 위치 지도 | Word로 PDF 변환 → 쪽마다 문항·지문 영역 좌표를 마크 기준 비율 좌표로 기록. 분석 키와 같은 번호 체계, `form.id`·버전과 연결 | `{학년}-{연-월}.map.json` |
| ③ 사진 업로드·분할 | 상담·등록 › 레벨테스트에서 쪽 사진 여러 장 업로드 → 사진 방향 보정 → 네 마크 찾기 → 기울기·원근 보정 → 몇 쪽인지 자동 식별(사진 순서 상관없이, 거꾸로 찍어도) → 틀린 문항 영역만 자르기 | 앱 기능 |
| ④ 리포트 삽입 | 자른 이미지를 기존 캡처 칸(`Lead.clips`)에 자동으로 채움. 원장은 확인·교체만 | 앱 기능 |

**대비책**: 마크를 못 찾으면 사진 위에서 네 모서리를 직접 찍게 하고, 그래도 안 되면 지금처럼 Ctrl+V 캡처.

**착수할 때 확인할 것**
- 원본 docx(`중1_영어_레벨테스트지.docx`)에는 머리글과 용지 설정이 없다(생성기 기본값) → A4·여백을 명시해야 하는지 Word로 변환해 쪽수·배치를 먼저 확인
- 학원 프린터로 출력했을 때 마크가 잘리지 않는지(인쇄 여백)
- 학생이 마크 위에 낙서하지 않게 안내, 사진 촬영 안내 문구(위에서 평평하게, 네 모서리가 다 나오게)
- 학년별 시험지가 늘어나면 시험지마다 ①②를 반복(시험지 파일이 바뀔 때마다 Claude가 갱신)

## 형식 (요약)
```
{ "form": {id, grade, version, totalItems, totalPoints, minutes},
  "skillCatalog": { "GR-PASSIVE": ["수동태", "문법"], ... },       // 코드 → [이름, 묶음]
  "passages": { "P1": {items:[33..36], skills:[...]} },            // 지문 구문 역량(간접 근거)
  "items": [ {no, area, unit, pts, kind:"mc|short|write", ans(mc만), skills:[..],
              d:{"보기번호":[결손 역량]}, err:{"역량코드":"오류 설명"}, passage, vocab:[..]} ] }
```

## 프로젝트 지침에 넣을 문안 (레벨테스트지 제작 프로젝트용)

> 테스트지를 만들 때마다 정답 해설과 별도로 **분석 키 JSON**을 같은 번호 체계로 함께 출력한다.
> 1. **skills**: 그 문항을 맞히는 데 필요한 역량 코드(1~3개). 독해 문항에도 필요한 문법·어휘 역량을 넣는다.
> 2. **d**(객관식): 정답이 아닌 보기마다, 그 보기를 골랐다면 어떤 역량이 부족한지 코드를 단다. 정답 해설의 "오답 체크"를 그대로 코드로 옮긴다. 의미 없는 보기는 생략한다.
> 3. **err**(서술형·영작): "흔한 오류"를 역량 코드와 한 줄 설명으로 단다. 부분 점수는 없으므로 점수는 쓰지 않는다.
> 9. 테스트지 네 모서리에 **정렬 마크**(검은 사각형)를 넣는다 — 학생 시험지 사진을 문항별로 자르는 기준이다.
> 4. **passages**: 독해 지문마다 지문에 쓰인 주요 구문(수동태·현재완료·관계대명사·가정 등)을 역량 코드로 단다.
> 5. **skillCatalog**: 기존 코드를 최대한 재사용한다. 새 코드가 필요하면 `GR-`(문법) `RD-`(독해) `VOC-`(단어) `WR-`(쓰기) 접두어로 추가하고 이름은 학부모가 이해할 말로 쓴다.
> 6. 문항 본문과 보기 문장은 키에 넣지 않는다. 배점·번호는 테스트지와 정확히 일치해야 한다.
> 7. **model**(서술형·영작): 정답 해설의 모범 답안을 한 줄로 넣는다(학부모 리포트에 그대로 보인다).
> 8. 단원명(unit)에 상위 학년 문항은 `(심화)`를 붙인다 — 분석에서 우선순위를 뒤로 미룬다.
